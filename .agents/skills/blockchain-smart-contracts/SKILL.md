# Blockchain and Smart Contracts
- Identify whether a blockchain is necessary and compare trusted database alternatives.
- Define chain, consensus assumptions, participants, permissions, privacy, and transaction costs.
- Specify contract state transitions, access control, events, upgrade policy, and failure behavior.
- Use established libraries and safe arithmetic; avoid custom cryptography.
- Test unit, integration, fuzz, invariant, and adversarial cases on local/test networks.
- Review reentrancy, access-control errors, oracle assumptions, front-running, and upgrade risks.
- Never deploy to mainnet or move funds without explicit approval and independent review.
Deliver architecture, threat model, test coverage, and deployment checklist. Do not claim an audit unless performed by qualified reviewers.
