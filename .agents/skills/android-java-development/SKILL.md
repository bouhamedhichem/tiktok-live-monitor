# Android Java Development
- Inspect the existing Gradle structure, SDK levels, Java version, manifest, and package conventions before changes.
- Use Java and XML when requested; keep Activities, Fragments, adapters, models, repositories, and services separated.
- Use lifecycle-aware patterns, ViewBinding where configured, and avoid retaining Activity contexts.
- Request runtime permissions only when needed and explain why.
- Keep network and database work off the main thread; handle lifecycle cancellation and failures.
- Support responsive layouts, accessibility, dark mode, and modern Android edge-to-edge behavior.
- Configure dependencies compatibly and preserve the Gradle wrapper.
- Test build, navigation, rotation, process recreation, permissions, and API-level behavior.
Deliver implementation notes, build/test results, and installation instructions. Never claim a successful build unless executed.
