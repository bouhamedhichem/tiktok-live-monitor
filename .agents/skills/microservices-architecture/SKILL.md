# Microservices Architecture

## Workflow
1. Define the product goal, users, scope, constraints, and measurable acceptance criteria.
2. Inspect the repository, platform versions, existing conventions, and dependencies before making changes.
3. Design maintainable architecture, data contracts, security boundaries, and operational ownership.
4. Implement incrementally with reusable components, clear interfaces, and documented configuration.
5. Validate inputs and outputs; apply secure defaults, privacy, accessibility, and least privilege.
6. Test success, invalid input, edge cases, failures, recovery, and realistic load.
7. Measure correctness, user experience, performance, reliability, and cost.
8. Document setup, deployment, monitoring, troubleshooting, backup, and rollback.

## Guardrails
- Use authorized systems, data, and assets; respect licenses and terms.
- Never commit credentials or expose privileged operations to clients.
- Preserve existing behavior and avoid unrelated modifications.
- Require approval for destructive or externally visible actions.
- Distinguish verified results from estimates, simulations, and generated content.

## Deliverables
- Requirements and architecture notes.
- Implementation and configuration instructions.
- Tests and validation evidence.
- Deployment, monitoring, maintenance, and rollback documentation.
