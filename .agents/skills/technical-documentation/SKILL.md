# Technical Documentation
- Identify audience, task, prerequisites, supported versions, and expected outcome.
- Organize around user tasks and information hierarchy.
- Include accurate setup, configuration, examples, troubleshooting, and verification steps.
- Keep examples runnable and use placeholders for secrets.
- Document architecture decisions, trade-offs, API contracts, and operational procedures.
- Check links, commands, version references, and consistency with the actual repository.
- Distinguish verified behavior from planned or experimental features.
Deliver concise, maintainable docs with update ownership where appropriate.
