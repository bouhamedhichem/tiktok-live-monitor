# Software Testing and QA
1. Understand acceptance criteria, architecture, critical user journeys, and risk areas.
2. Build a test matrix covering happy paths, boundaries, invalid inputs, permissions, concurrency, and recovery.
3. Choose unit, integration, contract, end-to-end, and exploratory tests at the appropriate layer.
4. Make tests deterministic; isolate external services and manage fixtures safely.
5. Verify accessibility, responsive behavior, browser/device coverage, and performance risks.
6. Record reproducible steps, expected/actual results, severity, evidence, and environment.
7. Re-run relevant regression tests after fixes.
Never claim a test passed unless it was executed. Distinguish not tested, blocked, failed, and passed.
